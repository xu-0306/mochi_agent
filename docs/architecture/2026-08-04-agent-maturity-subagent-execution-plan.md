# Plan PLAN-2026-08-04-MOCHI-MATURITY-SUBAGENT-01

## Objective

依據 Mochi 現況、reference 成熟專案與官方規格，將 agent 成熟度 roadmap 拆成 Main-owned 共享契約／持久化／副作用 seams 與可安全交付 subagent 的單一 production file 加單一 test file 葉節點；完成後由 Main 整合、qualification 與 release 判定。

## Main model

- Source: `current_conversation`
- Resolved model: ``
- Verification: `unavailable`

## Architecture decision

- Mode: `hybrid_main_seams`
- Profile: `full`
- Advisor required: `true`
- Reasons: Roadmap crosses runtime, SSE, persistence, WebGUI, migrations, cancellation and release gates, so shared contracts and final integration require Main authority.; Reference projects show stable reusable leaves only after versioned schemas, lifecycle policies and report formats are frozen.; Subagent identity cannot be authoritatively read back, so degraded routing limits each worker to at most one production file and one test file.

## Stop conditions

- Do not dispatch a worker package until all dependencies are integrated and its consumed contracts are frozen by Main.
- Do not dispatch while a package has overlapping same-wave ownership or exceeds degraded one-production/one-test limits.
- Stop dispatch and recompute MAP-EXECUTION-SCHEDULE-V1 when a dependency, owner, package, contract join, host slot count or calibrated duration changes; never treat the reference unit schedule as a calendar promise.
- Stop and replan if any worker requires shared lifecycle, persistence, migration, authorization, security, concurrency, transport or producer/consumer seam changes.
- Stop if a gate lacks an executable oracle or if a critical invariant would rely only on planner-authored evidence.
- Do not modify, stage, clean or overwrite mochi/runtime/sandbox/linux.py or tests/security/test_os_sandbox.py.
- Actual subagent creation is outside this planning turn and requires a later explicit user instruction.

## Fallback

- Mode: `main_takeover`
- Triggers: shared contract changes after freeze; worker needs a second production or second test file; model identity remains unavailable and package cannot be reduced safely; ownership overlap or migration/security boundary discovered; reference schedule is stale or actual worker capacity cannot satisfy its declared slot assumptions; worker reports blocked with evidence showing an unowned seam
